## 1. What it is (1 line)
3D game-style island website generated by AI agent (Antigravity + Gemini 4 Argon), data comes from Obsidian vault, notes rendered as books in a library on an island. Click book = read/edit. Same-note-type count = book count on shelf.

## 2. Trend context ("政策島")
- 政策島 = recent Taiwan trend: policy topics visualized as explorable 3D island (one building/area per policy).
- 圖書島 = same shell, reskinned to library + Obsidian notes.
- Pattern is generic: `X島 = X topic + island + walkable 3D + clickable hotspots + popup detail`. Can clone to any theme (罷免島, 建案島, etc).
- Why viral: looks like $10k award site, but agent builds it in minutes from a prompt + Three.js.

## 3. Tech stack (inferred, laziest that works)
- Builder: Google Antigravity (agent IDE, VS Code fork) + Gemini 4 Argon model. Any agent (Claude/Cursor/Windsurf) can substitute.
- Runtime: Three.js (CDN) for 3D island, plain HTML/CSS/JS. No backend needed for MVP.
- Data: Obsidian vault = folder of `.md` files. Parse frontmatter (title, tags, folder) at build time → `notes.json`.
- Hosting: single static page (like existing `彩虹機_找因數.html` in this repo). Docker/Cloud Run only if needed later.

## 4. MVP to build (YAGNI — single file first)
Single `index.html`, no build step:
1. `notes.json` — pre-exported from vault: `[{id, title, folder, tags, excerpt, path}]`. Script: `node export-notes.mjs ./vault > notes.json` (read .md, strip to 200 chars).
2. Scene: low-poly island (cylinder + cone trees), one library building, N bookshelves inside (N = distinct folder/tag).
3. Mapping rule (core idea): `books on shelf[i] = clamp(noteCount[i], 1, 20)` — more notes of same type = visually more books. Each book mesh = one note (cap 20 per shelf, "+N more" sign if overflow).
4. Interaction:
   - Orbit + WASD/joystick walk (reuse Three.js OrbitControls + simple first-person toggle, don't write custom engine).
   - Click book → side panel shows excerpt + buttons: [導讀 Read] [修改 Edit] [新增 New].
   - Edit/New = textarea → save to localStorage + export .md download (no real vault write in MVP; direct Obsidian write = later).
   - 導讀 = agent TTS/summary popup (call Gemini API only if key present, else show excerpt).
5. No login, no DB, no framework in MVP.

## 5. Data mapping (copy this)
```
vault/*.md → group by folder OR primary tag
folder/tag → one bookshelf (label = folder name)
note → one book spine (color = hash(tag), height ∝ word count)
click book → panel: title, tags, excerpt 200字, full-text link
```

## 6. Prompt to give the coding agent (paste verbatim)
> Build single-file `island.html` with Three.js via CDN. Load `notes.json` ([{id,title,folder,tags,excerpt}]). Render low-poly island + library with one bookshelf per folder. One book mesh per note, book count scales with note count. OrbitControls + click book opens side panel with title/excerpt + Edit (textarea → localStorage + .md download) + New note button. Keep it <600 lines, no build, no npm. Verify by opening file:// and clicking 3 books.

## 7. What NOT to build (skip)
- No backend/CMS, no real-time Obsidian sync, no auth, no multiplayer, no custom 3D models (use boxes/cylinders), no Mixamo character in MVP (add when static island works).
- Obsidian plugins (3D Embed, KMind Palace) are alternatives, not required — this is a standalone web export, not a plugin.

## 8. Verification
- Open `island.html` → island + library visible.
- Shelf count = folder count in `notes.json`.
- Click 3 books → correct title/excerpt.
- Edit saves to localStorage, reload persists.
- `ponytail: localStorage not real vault write; direct .obsidian write if round-trip matters.`
